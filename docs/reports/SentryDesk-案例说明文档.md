# 案例说明文档

> 案例名称：使用纳米Work完成安全情报本地聚合解析桌面工具的设计与开发
> 应用方向：AI+数字安全 ｜ 产出形式：桌面应用程序（Tauri 原生本地工具）
> 版本 v0.6.0 ｜ 全文约 2,300 字 ｜ 数据均为实测，可复现

---

## 一、行业背景

漏洞情报的获取方式正在成为中小企业和个人从业者的实际负担。CVE 编号发布在 NVD，供应链漏洞在 GitHub Security Advisory，已被在野利用的漏洞在 CISA KEV，处置建议散布在各国 CERT 与安全媒体的 RSS 里。这些源格式各异、更新频率不同，从业者只能人工逐站浏览、复制粘贴到表格里汇总，既耗时又容易漏掉高危条目。

现有商业威胁情报平台虽然能聚合多源，但它们是云端服务：使用者的关注列表、检索记录、笔记都要上传到第三方服务器。而一份关注列表往往直接反映企业"正在处置哪个漏洞、哪个产品暴露在哪个攻击面"，属于内部敏感信息。想跟踪，但不敢上云，这是真实存在的矛盾。

此外，安全知识教学与实战情报长期脱节：教材讲 CWE 原理用的是构造出来的示例代码，而真实漏洞情报里才有活生生的案例，学习者缺少把两者关联起来的工具。

## 二、解决的问题

SentryDesk（哨兵台）针对上述三个问题给出同一套方案：一款本地运行、数据不出机器的桌面工具。

1. **信息分散、人工汇总耗时**——内置合规采集器，只从 5 个白名单公开源（NVD CVE API 2.0、GitHub Security Advisory、CISA KEV、CISA News RSS、NCSC UK RSS）取公开信息，自动解析为结构化卡片存入本地 SQLite，一次采集 530 条只需 7–17 秒。
2. **不敢上云**——全链路在本机闭环：公开源 → 合规采集 → 本地解析 → 本地库 → 本地展示，链到此为止。无账号、无云同步、无任何数据上传，断网后检索与教学功能全部可用。
3. **学与用脱节**——内置 107 张中英双语教学卡（覆盖 34 个分类、329 道自测题、89 组"易受攻击/修复后"代码对比、91 条术语、10 条学习路径），并通过 CWE 编号与情报库双向关联：看到真实 CVE 一键跳到对应缺陷类型的教学卡，学完原理再回看真实案例。

合规不是口号而是代码：采集前先解析 robots.txt（RFC 9309 实现），按域名令牌桶限速，携带真实 UA，不碰登录态、不绕反爬、不伪造指纹，全程用"合规采集公开信息"这一种方式取数。

## 三、纳米Work 使用方式

本项目用"任务报告书先行"的方法与纳米Work 协作，而不是想到哪问到哪。开工前先写一份 993 行的工程任务报告书，把项目定义、6 条绝对禁止的合规红线、技术选型理由、T0–T7 八个阶段的验收标准、提问模板与排错模板全部定死，再分阶段投喂。协作遵循三条纪律：一次只解决一个问题；不接受"应该可以"，每一步必须给出验证命令和预期输出；边做边留存会话截图作为过程证据。

纳米Work 与人工的分工边界清晰：

| 环节 | 纳米Work 承担 | 人工承担 |
|---|---|---|
| 源调研 | 输出 5 个合规源的接口形式与限速规则 | 逐一实测可用性 |
| 架构与数据库 | 模块划分、建表 DDL、FTS5 同步触发器 | 审核语义、拍板取舍 |
| 采集与解析 | robots 解析、限速器、四类解析器代码 | 用真实数据校验 |
| 前端 | 16 个组件、设计 Token、中英词表 | 视觉微调 |
| 测试与文档 | 压力测试用例、文档初稿 | 实测验收、事实核对 |

效率可以直接用数字证明：11 月 10 日 13:10 确认环境通过，当天 21:57 产出 v0.4.1，次日 08:48 产出 v0.6.0——从空目录到功能完整的 12 个版本迭代不足 20 小时，全程单人。AI 的产出不是"听起来快"，而是每一版都有产物可验证：安装包逐版本留存（0.1.0 至 0.6.0 共 12 个），知识库完整性、中英覆盖率各有自动校验脚本，改完内容必跑。

排错过程同样体现"AI 提方案、人实测验证"的模式。典型一例：为做到目标机零配置，构建启用了静态链接 CRT，结果 Rust 的 ring 库内嵌 C 代码在 MSVC 下报 cl: D8050 编译错误。把完整报错按排错模板贴回，得到根因与两个候选方案，人工验证后落地为改用 native-tls。另一例：并发写入偶发 database is locked，定位为 DEFERRED 事务升级写锁时 busy_timeout 不生效，改为统一走 BEGIN IMMEDIATE 写事务入口后消除。每一个坑的根因与解法都写进了环境坑登记表，避免重复踩。

## 四、最终成果

技术栈为 Tauri 2 + Rust 内核（tokio、reqwest、rusqlite、quick-xml、scraper）+ SQLite/FTS5（trigram）+ Vue 3 + TypeScript，共 41 个 Tauri 命令、16 个前端组件、5 层单向依赖架构（组件 → 状态 → IPC → 命令 → 数据层），全部关键指标实测如下：

| 指标 | 实测值 |
|---|---|
| 数据库条目 | 530 条，CWE 覆盖 424/530（80%），库体积 4.20 MB |
| 检索延迟 | CVE 精确查询 0.010 ms；FTS 英文检索 0.032 ms |
| 冷启动到窗口可见 | 142–212 ms（多轮实测） |
| 主进程私有内存 | 8.1–9.5 MB |
| NSIS 安装包 | 2.97 MB，双击即用，无需安装任何运行库 |
| 内置教学库 | 107 卡 / 329 题 / 89 代码块，双语覆盖率 100% |

可靠性用压力测试说话：5 万次含重复写入不崩不重、写入后主表与全文索引一致性校验通过、7,200 次检索（含空词、恶意串）无一失败、4 线程并发写后 PRAGMA integrity_check 为 ok。交付形态为零配置：静态链接 CRT 后，目标机器只需 Windows 10/11 自带的 WebView2，删除数据目录重启即可自动重建全部表结构。

如实说明已知限制：右键菜单在部分 WebView2 环境下不可用；NVD 公开接口的 CWE 字段本身稀疏，导致该源 CWE 提取率低；教学内容未经第三方审校。这些限制均记录在案，不回避。

## 五、创新亮点

1. **教学库 × 情报库双向联动**。以 CWE 编号为外键，真实漏洞情报与 107 张教学卡互跳，把"刷资讯"和"学原理"合成一个动作，这在同类工具中少见。
2. **KEV 优先排序**。CISA KEV 不提供 CVSS 分值，按分数排序会让真正危险的在野利用漏洞沉底；本项目把"已被在野利用"作为排序第一键，再按 CVSS 与时间补位，解决了无分值数据的排序难题。
3. **合规内建而非声明**。robots.txt 按 RFC 9309 实现真实解析，采集前先检查许可，限速按域名独立令牌桶，违规的采集路径在代码层面就不存在。
4. **零配置交付**。静态 CRT + 单 exe，2.97 MB 安装包拷到任何 Win10/11 机器双击即用，对非技术用户和评审环境都友好。
5. **虚拟滚动**。固定行高 92px，10 万条数据只渲染 13–19 个 DOM 节点，列表不随数据量卡顿。
6. **可验证的 AI 效率案例**。传统流程下同等规模工具需要采集、数据、前端、文档四个角色协作约 2–3 周；本项目单人借助纳米Work 在约 20 小时内完成功能开发，AI 承担约 70% 代码生成与 100% 文档初稿，每个结论都有截图、产物和实测数字背书——这本身就是"AI 提升实际工作效率"的一次完整示范。
