## 三、缺陷清单与修复

### 高

**#1 Atom 源的条目全部取不到链接**
`parse/rss.rs` 只处理 `<link>` 的 Start 事件，而 Atom 规范用自闭合 `<link href="…"/>`，
产生的是 Empty 事件。结果是所有 Atom 源（CISA News 等）的条目要么被丢弃、要么落到假地址。
修复：新增 `Event::Empty` 分支提取 `href`。

**#2 无链接条目被塞进假地址**
原代码 `unwrap_or_else(|| format!("https://example.invalid/{}", source_key))`，
让没有 `<link>` 的条目也入库。用户点「原文链接」得到 404，且假地址参与 `content_hash` 去重。
修复：无链接直接丢弃。

### 中

**#3 收藏不存在的条目会抛 SQL 约束错误**
`toggle_favorite` 直接 INSERT，条目已被删（恢复备份、重新采集后列表残留旧 id）时报
`FOREIGN KEY constraint failed`，界面上是一句英文 SQL 报错。
修复：先查条目存在性，不存在安静返回 `false`。

**#4 检索排序缺少稳定次序键**
`ORDER BY in_kev, cvss, 时间` 在大量同分同日条目上不保证稳定，分页边界可能重复或漏行。
修复：追加 `i.id DESC` 作为最终次序键。

**#5 采集无重入保护**
`start_collect` 没有互斥，两个入口同时触发（或前端状态不同步）会并发跑两遍：
重复请求一次公网、进度事件互相覆盖、`collect://done` 发两次。
修复：`AppState` 增加 `AtomicBool` + RAII `CollectGuard`，`?` 提前返回也不会漏锁。

### 低

**#6 全局 Esc 缺失**：鼠标点开快捷键表后焦点不在浮层内，Esc 关不掉（只能点叉或背景）。
修复：`App.vue` 统一监听 Esc 关闭所有浮层。

**#7 NVD 描述语言判断冗余**：`(lang=="es"||lang=="zh") && lang=="zh"`，前半段恒真无意义。已简化。

**#8 `fmtBytes` 显示 `NaN MB`**：数值缺失时直接参与运算。修复：非有限值返回「—」。

**#9 User-Agent 版本号停在 0.6**：与产品版本不一致，对外声明失真。修复：改为 0.7.5。

**#10 切主题只改网页，不改 Windows 标题栏**：`applyTheme()` 只动 CSS 变量，原生标题栏
仍留旧色（浅色内容配深色标题栏）。修复：`theme.ts` 增加 `syncWindowTheme()` 调
`getCurrentWindow().setTheme()`，并在 capability 里补 `core:window:allow-set-theme`，
否则调用会被权限拦截。

### 本轮排查的一个假故障（值得记下来）

诊断阶段曾用 `start "" exe` + `sleep` + `tasklist` 的方式验证启动，连续几次看到「进程 6~10 秒后消失、窗口从未出现」，
于是按 WebView2 崩溃一路查（清 `EBWebView` 目录、换 `WEBVIEW2_USER_DATA_FOLDER`、同二进制换目录对照），
最终误判为「工作区路径触发了沙箱的 WebView2 限制」。

实际原因：**命令结束时，该会话里的子进程被一起回收**。进程不是崩了，是被收走了；那次带控制台的诊断构建报出的
`0x800700AA 请求的资源在使用中`，也是 WebView2 创建过程被中途掐断的后果，不是根因。

改为「同一条命令内完成启动 + 窗口枚举 + 截图」（Python `subprocess.Popen` → `EnumWindows` 按 PID 过滤 → `ImageGrab`）后，
新旧版本都能稳定出窗口。教训：进程消失时先怀疑测量工具。

### 发现并修复的缺陷

**损坏的数据库导致程序静默崩溃（P1，已修）**

- 现象：`sentrydesk.db` 被破坏后启动，进程 1 秒内退出（`0xC0000409`），无窗口、无任何用户可见提示。
- 原因：setup hook 返回 Err → `run().expect()` panic → release `panic = "abort"` 立即终止。
- 修复：`schema::open` 捕获 `SQLITE_NOTADB` / `SQLITE_CORRUPT`，把坏库（含 `-wal/-shm`）改名为
  `sentrydesk.db.corrupt-<时间戳>` 保留，写 `[recover]` 日志，重建空库后继续启动；其它错误仍照常报错。
- 复测：同一条件下正常出窗口，空态/看板 0/107 张卡/错题空态均正确，坏文件与日志都在。
- 回归：新增 2 个单测锁定该行为。

## 十、v0.8.4 追加：安装器占用自愈（2026-11-11 20:34）

### 用户报障

自主安装 0.8.3 时，安装进度到「正在安装」后弹出 NSIS 系统裸错误：

```
无法打开要写入的文件:
"C:\Users\17638\Desktop\CESHI\SentryDesk\sentrydesk.exe"
[中止(A)] [重试(R)] [忽略(I)]
```

没有上下文、没有处置建议，点重试仍是同一个框。

### 根因

- `File` 是编译期指令，运行时无法重试；写入失败只能由 NSIS 抛系统默认框。
- 模板自带的 `CheckIfAppIsRunning` 依赖 Restart Manager，对「安全软件扫描持有的句柄」、
  「进程刚退出句柄未释放」、「其它用户会话的实例」三种情况无效。
- **关键**：`tauri.conf.json` 从未配置 `bundle.windows.nsis.installerHooks`，模板第 36 行
  `!include "{{installer_hooks}}"` 被整行删除，导致第 788 行 `!ifmacrodef NSIS_HOOK_PREINSTALL`
  永远不成立——**安装钩子从未进入过任何一版安装包**。

### 修复与自测

新增 `installer-hooks.nsh` + 4 条双语文案，安装前先 taskkill 兜底、再轮询探测可写性（约 6 秒），
仍不可写才弹带排查步骤的重试框，放弃时清理占位文件退出，不留半成品。

| 验证项 | 结果 |
|---|---|
| 钩子执行、`$INSTDIR` 正确 | 调试日志记录 `INSTDIR=[...\SD_DBG_TGT]`，20 次探测后 ~6.2s 退出 |
| 失败路径干净 | 退出码 2、目标目录 0 文件、无 0 字节占位、无注册表残留 |
| 静默模式不卡死 | `/SD IDCANCEL` 生效，6.2s 结束 |
| 双语文案注册 | `makensis -V2` 无 `sdLock*` 的 6040 警告，仅余模板自带 `choowHowToInstall` 拼写警告 |

### 测试环境限制（重要）

当前构建环境（WorkBuddy 沙箱）把子进程降为 **Low 完整性级别**（安装器把日志写进了
`%LOCALAPPDATA%\Temp\Low\`），低完整性进程受 no-write-up 限制，任何普通目录都不可写，
因此「沙箱内跑安装器」得到的失败全部是环境假失败；`schtasks.exe` 被安全策略列入程序黑名单，
无法用它切到常规完整性。**结论：安装器全流程只能由用户在自己的桌面会话验证**，
沙箱内只能证明「编译正确 + 失败路径干净」。
