## v1.1.2 · 交互缺陷修复

**主题：四个用户能复现的交互缺陷。每一个都先定位根因，再决定改哪里——不做「看起来好了」的补丁。**

构建时间 11-12 15:05 ｜ 安装包 4,317,720 B（含签名）｜ 便携版 5,468,800 B ｜ 数据层无 schema 变更（仍为 v6）

### 修复

**① 命令面板执行错命令（点「设置」进复习、点「复习」进设置）**

两个下标体系不同源。`rows` 是按匹配分数排好序的数组，`grouped` 又把它们按
「检索 / 跳转 / 动作 / 教学卡 / 术语」固定顺序重新分桶，并用累加器 `idx` 给每组分配 `start`。
模板里点击与 Enter 用的是 `g.start + i`（显示顺序），`runAt()` 却拿这个下标去索引 `rows`（分数顺序）。
只要某个分组内部有重排，两个下标就差位——「设置」和「开始今日复习」恰好相邻，于是互相串台。

改法不是「把顺序对齐」这种碰运气的做法，而是让分组只负责显示：
每组额外保存 `idxs`（该组各行在 `rows` 里的真实下标），再派生出 `flatIdxs`（显示顺序的扁平映射）。
`runAt(i)` 先 `flatIdxs[i]` 拿到真实下标再取行。这样无论怎么重排都不会错。

**② 「稍后读」点了像没反应**

先排除了收藏功能本身：后端 `toggle_favorite` 有单测 `favorite_toggle_and_filter_are_consistent` 覆盖
（收藏 37 条 → `total` 等于收藏数 → 每条 `favorite` 为真 → 再点全部取消），40 个 Rust 测试全过。
真因在前端：收藏为空时，列表复用了「筛选过窄」的通用空状态，文案是「没有符合条件的条目 / 可放宽条件再试」。
用户点了「稍后读」，看到的是一个和之前没区别的空列表 + 一句「筛选太窄」，自然判断成按钮坏了。

改为专属空状态：星标图标、标题「稍后读还是空的」、提示「在任意条目的右上角点星标」、
按钮「看全部情报」（一键退出该筛选）。侧栏切换时另有 toast 说明命中条数，让状态变化可见。

**③ 部分教学类别点进去 0 条情报**

NVD 采集入口只取 `resultsPerPage=50&noRejected` 的最新 50 条。CWE 分布极度倾斜
（抽样 1200 条里 CWE-862 有 124 条、CWE-79 有 111 条、CWE-89 有 69 条），
教学卡里的冷门类别一条都落不到库里，点「本地情报库中该类型的真实漏洞」就是空列表。

先核实哪些类别「真的没有」、哪些「只是没采到」——直接查 NVD 的 `cweId` 接口：

| CWE | NVD totalResults | 结论 |
|---|---|---|
| CWE-327 | 428 | 有数据，补采 |
| CWE-311 | 252 | 有数据，补采 |
| CWE-330 | 283 | 有数据，补采 |
| CWE-799 | 2 | 有数据，补采 |
| CWE-1059 | 0 | NVD 侧就是 0 |
| CWE-1104 | 0 | NVD 侧就是 0 |
| CWE-29 | 0 | NVD 侧就是 0（该弱点在 NVD 统一归到 CWE-22）|

据此分两类处理：

- 有数据的四个类别：`entry_urls()` 增加 `cweId` 定向查询，每类 20 条。
  仍按 6 秒间隔串行（NVD 无 key 限 5 次/30s），NVD 段从 1 次请求变 5 次，约 30 秒
- 真没有的三个类别：不再渲染「0 →」可点按钮（点进去必然为空），
  改为静态说明块，如实写明「这一类属于设计/过程层面的弱点，NVD 不会为它分配 CVE 编号」

顺带修掉一个数据缺陷：`more_cwe.json` 里 `cwe-601-x` 这张卡写的是 `CWE-1021-x`，
不是合法编号（`CWE-\d+` 匹配不上），永远查不到条目。正文讲的是 CORS 配置过宽与
postMessage 未校验来源，实为 CWE-346，已改正（库内 9 条）。

**④ 右键「刷新界面」被踢回主页**

`window.location.reload()` 是整页重载。WebView 重新加载后 store 全部重新初始化，
`view` 回到默认值 `"home"`，于是用户在详情页、看板、错题本点刷新，都会被弹回主页。

改为 `refreshCurrentView()`：按当前 `view` 分别重取该视图需要的数据（检索结果 / 教学卡 /
路径 / 错题 / 收藏计数），界面停在原地。菜单文案也从「刷新界面」改成「刷新当前界面」。

### 变更

- 版本号 v1.0.5 → **v1.1.2**，四处同步：`package.json`、`src-tauri/Cargo.toml`、
  `src-tauri/tauri.conf.json`、`src/version.ts`；`Cargo.lock` 随之重新生成
- 固定 User-Agent 同步为 `SentryDesk/1.1.2`
- 采集入口重构：`entry_url()` 单数 → `entry_urls()` 复数。一个源可以有多个 URL，逐个过限速；
  任一 URL 失败不再整体失败，只要有一个成功就落库，全部失败才判定该源失败

### 工程

- Rust 单测 **40 个全通过**（含 `favorite_toggle_and_filter_are_consistent`）
- `vue-tsc --noEmit` **零错误**
- `cargo build --offline` 通过；因版本号变更，构建时 `Cargo.lock` 需重新生成（`--locked` 会报错，属预期）

## v1.0.5 · 参赛交付版

**主题：把「能演示」当成验收标准，14 项短板一次补齐，项目从本地文件夹变成公开仓库。**

### 新增

- **离线种子情报库**：`knowledge/seed/` 随包分发 CISA KEV 快照 1,779 条 + 近 30 天 CVE 1,200 条。

- **学习指标**：看板首排展示连续学习天数、待复习错题等 5 项。
- **状态栏数据时点**：显示「数据截至 YYYY-MM-DD」，让评审明白快照不是死数据。

  至此 CWE Top 25 全覆盖，且每张都带 bad/good 最小复现。
- 自测题 329 → **338 道**；中英双语覆盖率 100%。

### 修复

- **安装失败的四轮误诊终结**。真因是安全软件按进程拦截「未提权」安装器写 exe，
  不是占用（v0.8.4）、不是目录权限（v0.8.5）、也不是桌面保护（v0.8.6）。
  最终方案四件套：启动即申请管理员 + Authenticode 代码签名 + 用最终文件名真实写 1 字节探测 + 旧 exe 改名让位。
- 恢复目录页后引入的回归：上游模板的相对占位路径导致静默安装跑到桌面，
  改为绝对默认路径 + `.onInit` 判断同步修正。
- 并发写压测偶发 `database is locked`：测试用了 deferred 事务，锁升级时 `busy_timeout` 不生效。
  改用与产品写路径一致的 `BEGIN IMMEDIATE`，并用「双套件并行」实验完成复现 → 修复 → 验证闭环。
- 桌面残留单文件旧版导致版本漂移（旧 exe 内嵌旧内容，永远显示 v0.7.6）。
  确立发布纪律：只发 `setup.exe` 与 `portable.zip`，不投放裸 exe。

## v0.8.7 · 安装器真因定位

**主题：三轮误判之后，用户一句「以管理员身份运行就能装」把方向彻底扭转。**

构建时间 11-11 21:40 ｜ 安装包 3,230,512 B

### 修复

- 真因确认：安全软件按进程拦截**未提权**安装器落地 exe。此前 v0.8.5「目录改道」、v0.8.6「错误码保险」都是误判。
- 安装器 `RequestExecutionLevel admin`，启动即 UAC。
- 自签名证书签名主程序与安装包，顺带解决「发布者未知」提示。
- 写入探测改用**最终文件名**真实写 1 字节再删。杀软拦 `.exe` 不拦 `.tmp`，旧探测给出假阴性。
- 升级时先把运行中的旧 exe 改名为 `.old` 让位，取消安装则还原。
- 诊断日志 `%TEMP%\SentryDesk-setup.log`，单句柄三级路径回退。

## v0.8.4 · 安装器占用自愈

**主题：安装报「无法写入」的第一轮修复，先解决「程序在跑」这一类。**

构建时间 11-11 20:34 ｜ 安装包 3,229,438 B

### 修复

- **根因：安装钩子从来没被编进安装包**——`installerHooks` 配置缺失，此前所有钩子逻辑都是死代码。
- 安装时若程序正在运行，先结束进程再写入；失败时给可操作提示，而不是 NSIS 系统裸错误框。

### 工程

- 记录 NSIS 三个档案级坑（写进 hooks 文件头注释）：
  自定义宏必须在 `.nsh` 里定义、`!insertmacro` 顺序敏感、静默模式下 UI 宏不执行。

## 架构与工程演进

版本号之外，有几条贯穿全程的技术决策线。它们不是某一版的功能，但决定了后面每一版能不能改得动：

| 领域 | 起点（v0.1.0）| 终点（v1.0.5）| 演进原因 |
|---|---|---|---|
| 前端组件 | 单文件页面内联 | **21 个** .vue 组件 | 视图从 2 个增到 6 个，不拆分无法维护 |
| Tauri 命令 | 约 10 个 | **47 个**（8 个领域分组注册）| 采集、看板、导出、学习、设置、窗口各成一组 |
| 数据库 schema | v1 | **v6**（依次新增 favorites / wrong_answers / review / lesson_notes）| 收藏、错题、间隔重复、笔记依次落地 |
| 事务写法 | `Transaction::default()` | 统一 `write_tx()` → `BEGIN IMMEDIATE` | DEFERRED 锁升级时 `busy_timeout` 不生效，并发写报 locked |
| 全文检索 | FTS5 unicode61 | FTS5 **trigram** | 中文两字词也要能搜；2 字以下回退 LIKE |
| TLS | rustls（`ring`）| **native-tls** | `ring` 内嵌 C 代码在 MSVC 下报 `cl: D8050` |
| 构建 | 动态 CRT | **静态 CRT** | 目标机零配置，不需要装 VC++ 运行库 |
| 测试 | 手工点击 | 单元 + 流程 + 界面 + 端到端 + 压力 **五层** | 每版回归都要能跑，人工成本不可持续 |

### 五层测试体系（v0.8.3 定型）

| 层 | 内容 | 规模 |
|---|---|---|
| 单元 | Rust 侧函数级测试 | **40 个** |
| 流程 | 采集 → 入库 → 检索 → 展示 的链路 | 9 项 |
| 界面 | 视图切换、筛选、主题、语言 | 21 项 |
| 端到端 | CDP 驱动真实 WebView2 | **37 项** |
| 压力 | 5 万次写入、7,200 次检索、4 线程并发、20 次重开 | 5 项 |

压力测试的实测结论：

- 50,000 次含重复写入 → 20,000 条入库、30,000 条去重，不崩不重
- 7,200 次检索全部成功，最慢 31 ms，平均 5.85 ms
- 4 线程 × 500 次并发写 → `PRAGMA integrity_check` = ok
- 20 次重开 + 迁移 → 幂等，无残留

## 踩过的坑（按性质分类）

这些坑的共同点：**报错信息指向的地方不是问题所在**。所以单独归档，避免重复排查。

### 环境与构建

| 现象 | 真因 | 解法 |
|---|---|---|
| `cl: D8050` 编译失败 | `ring` 库内嵌 C 代码在 MSVC 下不兼容 | 改用 **native-tls** 替代 rustls |
| 增量编译慢到不可用 | dev profile 带完整调试信息 | `[profile.dev] debug = 0` |
| 目标机缺 VC++ 运行库 | 动态链接 CRT | 静态 CRT（`+crt-static`）|
| 构建成功但装的是旧代码 | 没走 `pnpm tauri build` | 必须用 tauri 构建链，不能单跑 `cargo build` |

### 数据库与并发

| 现象 | 真因 | 解法 |
|---|---|---|
| `CannotOpen`（extended_code 14）在第 594 条左右 | `TMP` / `USERPROFILE` 未设置，SQLite 建不了临时文件 | `PRAGMA temp_store = MEMORY` |
| 并发写偶发 `database is locked` | DEFERRED 事务升级写锁时 `busy_timeout` 不生效 | 统一 `BEGIN IMMEDIATE` |
| 搜 1–2 个字直接报错 | `search_items` 的 LIKE 分支把参数压了两次 → `InvalidParameterCount(7, 6)` | 参数只构建一次，COUNT 与列表共用 |
| 库损坏后双击没反应 | 打开时没校验完整性 | `PRAGMA integrity_check` + 备份为 `.corrupt-<时间戳>` 并重建 |

### 前端与运行时

| 现象 | 真因 | 解法 |
|---|---|---|
| 子组件 `flex:1` 不生效、滚动条不出来 | Vue 3 的 `<slot />` 不产生 DOM，flex 链条断了 | 用真实元素包一层 |
| 清空筛选后搜索框还留着旧词 | 搜索词是组件局部状态 | 提升到 store 的 `searchInput` |
| 结果集变少后列表空白 | 虚拟滚动位置越界 | `watch(items)` 时 `clampScroll()` |
| 右键菜单在 WebView2 里不弹 | 宿主窗口默认菜单抢先消费事件 | **转为已知限制**，三轮尝试后放弃 |
| 看板「按分类」永远是 0 | 统计口径没和掌握记录取交集 | 用 id 集合求交 |

### 安装与发布

| 现象 | 真因 | 解法 |
|---|---|---|
| 安装弹 NSIS 裸错误框 | `installerHooks` 配置缺失，钩子从未编进包 | 补配置（v0.8.4）|
| 装了新版仍显示旧版本号 | 桌面残留单文件旧 exe，内嵌旧内容 | 发布纪律：只发 `setup.exe` 与 `portable.zip` |
| 安装失败四轮误诊 | 杀软按进程拦截**未提权**安装器写 exe | 启动即 UAC + 代码签名 + 最终文件名真实写探测 |
| 便携版中文名乱码 | 资源管理器按 GBK 写 zip | Python `zipfile` 写 UTF-8 标志位 |
| 覆盖 exe 后自动更新装不上 | 安装包字节变了，`.sig` 失效 | 改完安装包必须重签 |

## 三条纪律

写进流程、不靠记性的三条：

1. **调试输出必须清理**。v0.5.0 的设置页残留了 `DEBUG sources.length=5`，截图里一眼就能看到。
2. **产物验证要核对文件修改时间**。构建成功不等于产物更新，QA 两次跑到旧代码上。
3. **不投放裸 exe**。只发安装包与便携版，避免版本漂移。
