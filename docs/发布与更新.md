# 发布与自动更新

本文说明如何发布一个可被应用内「检查更新」拉取的新版本。

> 现状：应用内更新端点为
> `https://github.com/MenLan-ov/SentryDesk/releases/latest/download/latest.json`
>
> ⚠️ **私有仓库的 Release 资产无法匿名下载**：仓库必须设为 Public，
> 应用内的自动更新才能在评委/用户机器上生效。若保持 Private，
> 「检查更新」会走降级分支，提示「可直接用新版安装包覆盖安装」——功能不崩，但更新不可用。

---

## 一、安装包为什么需要两个签名

| 签名 | 用途 | 产物 |
|---|---|---|
| Authenticode（自签名证书） | 让 Windows 显示发布者、通过 UAC 校验 | exe 内的签名 |
| minisign（`tauri signer`） | 让 `tauri-plugin-updater` 校验更新包完整性 | `.sig` 文件 |

两者独立：前者防「来源不明」，后者防「更新包被篡改」。

- 证书：`_tools/sign/SentryDesk.cer`（指纹 `ACE77E8E…`，有效期至 2031-11-11）
- 更新私钥：`_tools/sign/updater.key`（**不要进仓库**，已在 `.gitignore`）
- 更新公钥：写在 `src-tauri/tauri.conf.json` 的 `plugins.updater.pubkey`

## 二、发版流程

```bash
# 1) 改版本号（四处必须一致）
#    package.json / src-tauri/Cargo.toml / src-tauri/tauri.conf.json / src/version.ts

# 2) 构建（带更新签名私钥，产出 setup + .sig）
export TAURI_SIGNING_PRIVATE_KEY="$(cat ../_tools/sign/updater.key)"
export TAURI_SIGNING_PRIVATE_KEY_PASSWORD=""
pnpm run build
npx tauri build --bundles nsis

# 3) 签 Authenticode（主程序 + 安装包）
signtool sign /sha1 ACE77E8E1A8D84C5C3E34AA281E48FEFCD9E4BB4 /fd SHA256 ^
  src-tauri\target\release\sentrydesk.exe
# 用已签 exe 重新打安装包，再签安装包本体
cd src-tauri\target\release\nsis\x64
makensis -INPUTCHARSET UTF8 installer.nsi
signtool sign /sha1 ACE77E8E... nsis-output.exe
copy nsis-output.exe ..\..\bundle\nsis\SentryDesk_<版本>_x64-setup.exe

# 4) 安装包字节已变，更新签名必须重签
echo "" | npx tauri signer sign --private-key-path ..\..\_tools\sign\updater.key ^
  ..\..\bundle\nsis\SentryDesk_<版本>_x64-setup.exe

# 5) 便携版（可选）
#    解压产物到 SentryDesk\ 目录，压 zip 时用 UTF-8 文件名（见下）
```

### 便携版打包注意

Windows 资源管理器「发送到压缩文件夹」会把中文名按 GBK 写入，解压后变乱码
（曾出现 `õ¢+þö¿Þ»¦µÄ.txt`）。请用 Python 的 `zipfile`（自动写 UTF-8 标志位）：

```python
import zipfile, os
with zipfile.ZipFile("SentryDesk_<版本>_portable.zip", "w", zipfile.ZIP_DEFLATED) as z:
    for root, _, files in os.walk("stage"):
        for f in files:
            p = os.path.join(root, f)
            z.write(p, os.path.relpath(p, "stage"))
```

## 三、Release 资产与 latest.json

一次 Release 需要上传：

| 资产 | 说明 |
|---|---|
| `SentryDesk_<版本>_x64-setup.exe` | 安装包（附带 Authenticode 签名） |
| `SentryDesk_<版本>_x64-setup.exe.sig` | 更新签名（`tauri signer` 产物） |
| `SentryDesk_<版本>_portable.zip` | 便携版（可选） |
| `latest.json` | 更新清单（见下） |

`latest.json` 模板（`signature` 填 `.sig` 文件的**完整内容**）：

```json
{
  "version": "1.0.5",
  "notes": "修复安装位置不可选；补齐 CWE Top 25；首启导入 2979 条情报。",
  "pub_date": "2026-11-11T23:30:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "<SentryDesk_1.0.5_x64-setup.exe.sig 的全部内容>",
      "url": "https://github.com/MenLan-ov/SentryDesk/releases/download/v1.0.5/SentryDesk_1.0.5_x64-setup.exe"
    }
  }
}
```

发布后地址为：
`https://github.com/MenLan-ov/SentryDesk/releases/latest/download/latest.json`

## 四、安装器签名证书

首次在新机器上安装时，若未导入自签名证书，UAC 会显示「未知发布者」。导入一次即可：

```bat
certutil -addstore -user -f Root            _tools\sign\SentryDesk.cer
certutil -addstore -user -f TrustedPublisher _tools\sign\SentryDesk.cer
```

或用 `_tools/sign/导入证书.bat`（带说明与卸载指引，交互式）。

> 非交互环境（脚本/CI）里 `Import-Certificate` 会报「此操作中不允许使用 UI」，
> 必须用 `certutil` + `-f` 静默导入。

## 五、发布检查清单

- [ ] 四处版本号一致
- [ ] `cargo test` 全过、`vue-tsc --noEmit` 零错误
- [ ] `python _tools/ci/check_knowledge.py` 通过
- [ ] 安装包 Authenticode 验证 `Valid`
- [ ] `.sig` 与安装包**同一次构建**（覆盖 exe 后必须重签）
- [ ] `latest.json` 的 `version` 高于已发布版本
- [ ] 仓库为 Public（否则自动更新不可用）
- [ ] 真机跑一遍：安装 → 打开 → 情报页有数据 → 学一张卡 → 做一道题
