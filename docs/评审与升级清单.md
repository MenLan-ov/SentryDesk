## 一、总体判断（v0.8.7 基线，已被第七节取代）

> ⚠️ 本节及第二～五节描述的是 v0.8.7 的状态，保留下来是为了记录改进过程。
> 文中「README 还是模板」「首装情报页为空」「107 张卡」等表述**均已不成立**，
> 请以第七节的复评为准。

**工程底子够格，当时交付形态不够格。**


代码层面这是一份有竞争力的作品：Tauri 2 + Rust + SQLite FTS5 + Vue 3 + TypeScript，
Rust 约 6000 行、前端约 7400 行，45 个单元测试，四层依赖方向清楚，有架构文档、
有错误边界、有数据库损坏自恢复、i18n 中英各 81 键完全对齐、0 处 TODO。
内容侧 107 张教学卡、329 道自测题、91 条术语、10 条学习路径，全部为中英文双语，
题目数量与代码统计完全吻合（不是编的）。

但只要评委装上就点，会撞到两个与技术水平无关、却极其致命的坑（见第二节）。
这两个坑不补，作品会给人「演示不出来」的第一印象，前面所有工程努力都会被折价。

## 二、两个必须先修的致命问题

### 问题 1：全新安装后，情报页是空的，而且没有任何入口能填

这是最严重的一条，务必先修。

**证据链：**

- `tauri.conf.json` 的 `bundle.resources` 只有 `../knowledge/*.json`，**安装包里没有数据库**；
- 项目内不存在任何 `.db` 种子文件（`find . -name '*.db'` 只命中测试临时库）；
- `db/schema.rs::open()` 只执行 DDL（`CREATE TABLE IF NOT EXISTS`），**不写入任何初始数据**；
- `db/schema.rs` 里 `INSERT` 只出现在 FTS 触发器与测试中；
- v0.8.5 「去爬虫化」时，我把侧栏的「开始采集」按钮删掉了，改成一行说明文字；
  后端 `cmd/collect.rs::start_collect` 命令还在，但**前端已无任何调用点**。

**后果：** 评委双击安装、打开应用、点「情报」→ 0 条结果、来源计数全 0。
而安装向导的欢迎页写着「587 条漏洞条目，每条标注信息来源」——**宣传与实物不符**，
这比功能少更扣分。

**修法（二选一，建议都做）：**

1. **打包种子库**：用 CISA KEV 官方 JSON（单次请求约 1200 条，含 CVE、厂商、产品、
   描述、收录日期）+ 近期 NVD 条目生成 `seed.db`，加入 `bundle.resources`；
   启动时若 `items` 表为空则一次性导入。这样「587 条随包分发」变成真的，且离线可用。
2. **恢复导入入口**：设置 → 数据 → 「导入内置情报库」按钮，调用已有的 `start_collect`
   或直接从 resources 导入。至少让用户有路可走。

### 问题 2：README 还是脚手架原文

```
# Tauri + Vue + TypeScript
This template should help get you started developing with Vue 3 and TypeScript in Vite.
```

评委看仓库第一眼就是它。这一份文件的价值被完全浪费了：项目真正的卖点
（107 卡 / 329 题 / 离线 / 无遥测 / 合规采集 / 安装器占用自愈）一个字都没写。

**修法：** 重写 README，结构建议——一句话定位 → 截图（现版本、中文）→ 三条核心能力
→ 技术架构图 → 如何构建/运行 → 数据来源与合规声明 → 版本历史 → 许可。

## 四、答辩叙事建议

现在这个项目最好讲的故事不是「我做了一个漏洞库」（同类太多），而是：

> **「一个离线、可审计、不联网的安全学习工作台——把公网情报变成可教学、可自测、可复习的知识资产。」**

三个支撑点，每个都有代码/数据可现场验证：

1. **离线与本地优先**：SQLite + FTS5，断网可用，无账号、无遥测（设置页可证）；
2. **合规采集**：robots 校验、限速、User-Agent 固定（后端仍在，可现场演示源码）；
3. **教学闭环**：情报 → 关联 CWE → 教学卡 → 自测 → 错题复习 → 路径推进（可现场走一遍）。

⚠️ 注意第 3 点依赖「首装就有数据」，所以 P0-1 必须做，否则闭环在评委机器上走不通。

## 八、v1.1.2 复评（当前结论｜2026-11-12）

### 8.1 这一轮改了什么

四个用户能复现的交互缺陷。共同点是**都不属于「功能缺失」，而是实现细节错位**，
所以修复的关键是先定位根因，而不是加功能或改文案糊过去。

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 命令面板点「设置」进复习、点「复习」进设置 | 显示下标与数据下标两套体系混用 | 分组只做显示重排，另存真实下标映射 |
| 2 | 「稍后读」点了像没反应 | 收藏为空时复用通用「筛选过窄」空状态 | 专属空状态 + 切换 toast |
| 3 | 部分教学类别点进去 0 条 | NVD 只取最新 50 条，CWE 分布倾斜 | 按 `cweId` 定向补采 4 类 |
| 4 | 右键刷新被踢回主页 | `window.location.reload()` 重置 store | `refreshCurrentView()` 原地刷新 |

### 8.2 实测口径

| 检查项 | 命令/方式 | 结果 |
|---|---|---|
| Rust 单测 | `cargo test --offline` | **40 passed / 0 failed** |
| 前端类型 | `pnpm exec vue-tsc --noEmit` | **0 错误** |
| Rust 构建 | `cargo build --offline` | 通过，`Cargo.lock` 版本已同步 1.1.2 |
| 版本号一致性 | 四处 grep | `package.json` / `Cargo.toml` / `tauri.conf.json` / `version.ts` 全为 1.1.2 |
| NVD 类别核实 | `cweId` 接口直查 | CWE-327=428、CWE-311=252、CWE-330=283、CWE-799=2、CWE-1059/1104/29=**0** |
| 数据缺陷 | 全量扫 `knowledge/*.json` 的 `cwe` 字段 | 发现 1 处非法值 `CWE-1021-x`，已改 `CWE-346` |

### 8.3 一个必须说清的点

第 3 项修复里，有 3 个类别（CWE-1059 / CWE-1104 / CWE-29）在 NVD 侧**确实是 0 条**，
不是采集没采到。这三类属于设计/过程层面的弱点，NVD 不会为它们分配 CVE 编号。
所以正确处理不是「想办法凑出数据」，而是**不再给一个必然为空的入口**，如实写明原因。

这也是本轮唯一的取舍：宁可让界面少一个可点按钮，也不制造「点了没东西」的第二次失望。

### 8.4 v1.1.2 实测数字（2026-11-12）

| 指标 | v1.0.5 | v1.1.2 | 测法 |
|---|---|---|---|
| 冷启动（到窗口句柄有效）| 177 ms | **684 ms** | 见下方说明 |
| 私有内存 | 8.4 MB | **8.5 MB** | `PrivateMemorySize64` |
| 工作集 | 29.6 MB | **32.2 MB** | `WorkingSet64` |
| 安装包 | 4,311,832 B | **4,317,720 B** | NSIS 产物（含 Authenticode 签名）|
| 便携版 zip | 5,643,423 B | **5,468,800 B** | 7z -mx=9 |
| 裸 exe | 8,508,416 B | **10,549,248 B** | — |
| Rust 单测 | 40 passed | **40 passed** | `cargo test` |

冷启动 684 ms 比 v1.0.5 的 177 ms 慢，原因不是代码变慢，而是
**测量口径变了**：v1.0.5 的 177 ms 取自应用自身日志打点（进程内计时），
本次 684 ms 是从「spawn 到 `MainWindowHandle` 非零」的外部轮询，
包含进程创建、WebView2 初始化与首帧绘制，口径更严。
两者不可直接相减，后续统一用外部轮询口径复测。

### 8.5 一个容易误判的「启动即崩」

本轮验证时踩到一个坑，值得写下来：把 `target/release/sentrydesk.exe` 直接双击运行，
进程以 `0xC0000409` 立刻退出，日志一行都不写，看上去像严重崩溃。

实测真因**不是代码问题**：

- 同一份 exe 复制到「exe + knowledge/ 同级」的安装布局下启动，窗口正常打开
- 在 `target/release/` 原地运行才崩
- debug 构建能打印出真实原因：
  `failed to create webview: WebView2 error: HRESULT(0x800700AA) 请求的资源在使用中`

也就是说，这是 WebView2 在特定工作目录下初始化失败，与业务逻辑无关；
之前记录的「release exe 启动 exit=3221226505」结论应据此修正——
**验证发布产物必须在安装布局下进行，直接在 target 目录里点 exe 会得到假阴性**。

### 8.6 仍未解决（如实记录）

- 右键自定义菜单在 WebView2 下无法完整接管（v0.3.1–v0.3.3 三次尝试均失败），
